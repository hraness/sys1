## Method

The frozen corpus contains 24 development examples and 24 screening examples.
Each of the three workflows has eight examples per split. A separate Codex
worker authored the screening examples after reading the rubrics and development
cases, before any model results were available. They use fictional source
families and were held out from profile changes for this run. The small authored
set does not establish performance on real tasks. Calibration, correction effort,
follow-up reading, and time saved were not measured.

The baselines use diagnostic signatures for triage, token overlap for relevance,
and literal matches with simple negation for claim support. The claim comparator is weak and predicts
`insufficient_evidence` for every case in these two splits. Relevance labels measure answer coverage, including for
unverified excerpts; the workflow does not discard excerpts.

The harness ran serialized requests in the table's order on Bun 1.3.14,
Linux x64, in a temporary Vercel preview build. It pinned
`typesafe/jev-1.13.0`, disabled local routing, and used no retries. Every completed
response reported backend `typesafe`, model `jev-1.13.0`, and one attempt. These
returned names are observations, not independent checkpoint verification. Expected
labels were used for local grading and were excluded from inference requests.
A unique highest-probability answer determined the grade; a tie would be
unresolved. No completed answer tied.

The run allowed at most 48 model submissions, 96 discovery requests, and 14
minutes overall. Per-request limits were 30 seconds in the evaluator, 20 seconds
in the gateway, and 1.5 seconds for discovery probes. The first gateway error
stopped further model submissions.

## Timing and recorded usage

Median completed-case times were 333.5 ms for triage development and 337.0 ms for
triage screening. The single completed relevance case took 323.4 ms. These times
include the local client, loopback gateway, provider discovery and inference, and
response validation. They exclude deployment, build, bundling, input validation,
gateway startup, and baseline calculation. The serialized execution order and
small sample do not support a controlled latency comparison.

The report's start-to-finish interval was 6.114 seconds, including gateway startup
and shutdown. The build region was unavailable. The 17 completed responses
reported 12,686 input tokens and 1,303 output tokens. Failed-request token usage
and monetary cost are unavailable.
