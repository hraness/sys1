Introducing Sys1

Give your coding agent a repeatable way to review a change and check what it says is done.

Hraness

A coding task leaves several things to inspect: the test result, the changed code, and the agent’s final message. Sys1 gives the agent commands and project instructions for those moments, with a result it can investigate before moving on.

The separate system-one-verify skill condenses a noisy check into its exit status and a short excerpt. Sys1’s sys1-review and sys1-verify skills add optional model-assisted review and completion checks. Install the one that fits your task, then ask your agent to use it.

Start with the part of your workflow that needs attention. Compact output runs locally; review and completion checks use your chosen model.

Noisy test logs come back as a short result

The separate system-one-verify skill returns a check's exit status and a short excerpt, keeping the full log on disk. Across 563 recorded outputs, replay returned 35% less text. It needs no model.

Review changes against your own rules

Use sys1 review to check selected changes against repository rules, such as keeping test assertions or handling errors. Each advisory finding names the rule and source location for your agent to investigate.

Set up code review

Check the agent's completion message

Use sys1 verify to compare a proposed completion message with Git, linked pull requests, and live pages. It reports agreement, contradictions, and unavailable evidence. Inspect the advisory result before relying on the claim.

Set up completion checks

Work through the finding

Suppose your agent adds validation to an endpoint. The tests pass, but the diff includes a new empty catch block. A review checkpoint combines that diff with the repository’s error-handling rule and returns a candidate finding at the relevant line.

The agent reads the surrounding code and confirms whether an error can be swallowed. If it finds a defect, it repairs the change and reruns the tests. It then records the finding as useful, incorrect, or unverifiable. That investigation is part of the workflow.

A preview makes no model calls. A complete, unchanged batch can be reused for up to 24 hours, and repeated findings stay out of new output. Your feedback remains in the local review history. After a repair changes the source, run a new checkpoint on the changed evidence.

Completion checking follows the same principle. If the message says “pushed” while commits are still ahead of the upstream branch, the Git evidence contradicts that claim. Missing evidence stays unverifiable. File or stdin input works with any agent; check-command evidence comes from local Devin transcripts.

Add a project skill

After installing Sys1, run setup inside the repository where your agent works. Preview the destination, then write the instructions. Setup makes no model calls.

Add review instructions for Codex
sys1 review setup codex --dry-run --json
sys1 review setup codex --json

Use setup claude-code or setup devin for those agents. Use sys1 verify setup to add completion checks. The skill file belongs to the project, so you can review and commit it with the repository.

For model-assisted checks, choose a backend before running a checkpoint. Hosted Jev requires TYPESAFE_API_KEY in your environment and sys1 jev enable. Selected source and message excerpts go to that backend. A dry run lets you inspect the selection first.

Ask your agent: “Run a Sys1 review checkpoint on the files in this change, investigate the findings, and record the feedback.” The review guide covers the commands; the completion guide covers the final message. For a model-free first step, install compact check output.

Use the decision API in your application

Sys1 also offers a Node/Bun client and a local HTTP gateway. Your application supplies a question with a declared answer shape: yes/no, a choice among named options, or a score. The response contains the answer, probabilities, and the backend that answered.

The API guide shows the request format and client code. Route to TypeSafe’s hosted Jev, an installed local model, or a compatible server you configure. Sys1 validates the response against the question. Evaluate the model on examples from your application before relying on its judgments.

What the results cover

Compact output returned 35% less text across 563 recorded check outputs in replay. The full logs stayed available, and every preservation check passed. That measures the output the agent receives; whole-task token and time savings have not been demonstrated.

In separate whole-task trials, agents did not voluntarily call either skill. Requiring review used more tokens and time and reduced correctness on the tested tasks. Ask for the check explicitly and judge its usefulness on your repository.

The completed 60-run completion baseline stayed below its registered intervention threshold. It measured unassisted completion claims and did not test the accuracy of sys1 verify.

Review and completion checks remain experimental and advisory. The bundled review rules check newly empty catch blocks and removed test assertions in JavaScript and TypeScript. Local Qwen models are experimental. Model probabilities do not establish calibrated accuracy; keep the repository’s tests and review.

The compact-output evidence, whole-task reports, and decision-profile screen preserve the measurements and their limits.
