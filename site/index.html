System

Review your agent’s changes.

Sys1 is an open-source CLI and agent skill for Codex, Claude Code, and Devin. It checks Git changes against your repository’s rules before you open a pull request, and checks the agent’s completion claims. Answers come from Jev, TypeSafe’s hosted decision model, a local model, or a compatible server you run.

Give your agent a review checkpoint.

The sys1-review project skill guides Codex, Claude Code, or Devin through the same workflow. Start with checks for newly empty catch blocks and removed test assertions in JavaScript and TypeScript, or add your own rules.

  1. Install the project instructions

    Run sys1 review setup codex, claude-code, or devin inside your Git repository. Setup adds a skill file; it does not enable a model or install automatic hooks.

  2. Preview a batch of changes

    Choose worktree, staged, or committed changes. A dry run lists the selected rules, files, skipped evidence, and planned requests before any source goes to the model.

  3. Investigate and keep feedback

    Run the checkpoint, inspect each candidate in the code, and mark it useful, incorrect, or unverifiable. Complete unchanged batches can reuse a review for up to 24 hours.

Review is experimental. Scores help rank candidates; they are not calibrated defect probabilities, and an empty report does not prove correctness. Keep your repository’s tests and review. Set up agent review.

Check the completion message

The sys1-verify project skill runs sys1 verify to compare claims about commits, merges, checks, and live pages with reachable evidence. Install it with sys1 verify setup codex, claude-code, or devin, and pass a saved message from your agent.

Call a Jev-compatible API from your app.

Sys1 serves TypeSafe’s System One API, POST /v1/systemone, on 127.0.0.1 and ships a Node and Bun client. Send the same request to hosted Jev, a local Qwen model, or an OpenJev server you run, and your code gets one validated answer format. Local Qwen answers approximate Jev; they are not calibrated Jev output.

  1. Ask a typed question

    Send some state and one or more questions. A noul question, Jev’s yes/no type, returns a probability; choice picks one of your named options; and score returns a number over your ordered criteria.

  2. Sys1 sends it to the model you picked

    A local Qwen model, hosted Jev, or a compatible server you registered. Pin the backend and model in configuration; the local-only policy keeps requests on your machine.

  3. Your code gets a checked answer

    Sys1 rejects malformed answers, carries cancellation through the request, and reports which backend answered. Answers from built-in local models also name the adapter.

  4. Your app decides what happens next

    Permissions, thresholds, and follow-up actions stay in your code. Sys1 does not estimate accuracy per request.

One request and its answer

Three ways to call Sys1.

All three take the same request and return the same answer format.

Node & Bun client
@hraness/sys1/client

Typed requests, validated responses, and cancellation. Installs without the optional native runtime.

Embedded Bun router
createRouter()

Routing and local models run inside your Bun app. Call dispose() when you finish.

Local HTTP daemon
POST /v1/systemone

Listens on loopback only (127.0.0.1 by default), for Rust, Python, and other languages. sys1 up, sys1 status, and sys1 down manage it.

Inside your applicationTypeScript
import { createClient } from "@hraness/sys1/client";

const sys1 = createClient();
const { response, metadata } = await sys1.evaluate({
  state: "The build failed after a dependency update.",
  questions: {
    next: {
      type: "choice",
      criteria: {
        repair: "Fix the build",
        continue: "Continue work"
      }
    }
  }
});

console.log(response.answers.next);
console.log(metadata.backend);

What Sys1 connects to.

Every backend answers in the same format, but not equally well. Accuracy and calibration differ by model, so test each one on your task before you reuse thresholds or change defaults. Compare the models.

BackendWhat it isHow Sys1 uses it
Qwen3 1.7BLocal model, experimental

The default local model, run on your hardware.

sys1 setup downloads verified weights and turns it on. It stays selected when you install another model.

JevHosted, opt-in

TypeSafe’s hosted System One decision model.

Off until you run sys1 jev enable with your own TypeSafe API key. Enabling it selects hosted-only routing, so requests do not fall back to a local model.

OpenJevSelf-hosted server

An open implementation of a Jev-compatible decision API.

Register a server you run and test it with sys1 backend check. Image, chat, and advanced sampling extensions are not supported.

llama.cppLocal runtime

Native local inference, through node-llama-cpp.

Sys1 loads the model, cancels requests, and maps first-token probabilities to answers.

Before you begin.

How is Sys1 different from CodeRabbit, Cursor Bugbot, or Claude Code Review?

Those are hosted AI reviewers that look for many kinds of bugs. Bugbot and Claude Code Review comment on pull requests, and the CodeRabbit CLI also reviews local changes. For broad bug-finding they cover more than Sys1, whose bundled rules cover two JavaScript and TypeScript checks. Sys1 checks only the rules you select, can keep your source on your machine with a local model, and lets you record whether each candidate was useful. For a pure syntax pattern such as an empty catch block, an ESLint or Semgrep rule is exact and free; use Sys1 for rules that need judgment.

Can everything stay local?

Yes, for decision requests using local models and the local-only routing policy. Installing Sys1 and running model setup download packages and weights. Hosted Jev is off by default.

Can I replace my existing Jev client?

Yes. Run sys1 jev enable, which turns on hosted Jev and sets routing to hosted-only so no request falls back to a local model. Pin jev-1.13.0 so your app keeps the same model while you switch to the Sys1 client. Test your request sizes, question limits, cancellation, and error handling. Read the adoption guide.

Does Sys1 pick the most accurate model?

No. You choose the model. Fresh setup uses Qwen3 1.7B; enabling Jev selects hosted-only operation, and a hosted outage returns an error. Local fallback needs an explicit policy change after you evaluate it. Installing a smaller model does not change the selection.

What does it cost?

Sys1 is free, open-source software under the MIT license. Local inference uses your hardware. Hosted providers may charge separately under their own plans.

How do I keep noisy test logs out of my agent’s context?

System One Skills provides the separate system-one-verify skill for Devin, Claude Code, and Codex. It runs a known noisy check once, returns a short result, and keeps the full log on disk. It works without Sys1 or any model backend.
