import { createClient } from "@hraness/sys1/client";

const sys1 = createClient();
const { response, metadata } = await sys1.evaluate({
  state: "The build failed after a dependency update.",
  questions: {
    next: {
      type: "choice",
      criteria: {
        repair: "Fix the build",
        continue: "Continue work"
      }
    }
  }
});

console.log(response.answers.next);
console.log(metadata.backend);

Good models deserve
a shared interface.

Sys1 is the routing and integration layer around models and services. These projects supply different capabilities; Sys1 brings their supported decision paths into one application contract.

ProjectWhat it providesHow Sys1 uses it
Jev Hosted provider

Typed decisions through the System One API.

An optional hosted backend. Enable it explicitly with your own credential; keep the same request shape as local calls.

OpenJev Self-hosted server

An open implementation of a Jev-compatible decision API.

Connect and qualify a server you operate. Sys1 uses its common decision interface; the OpenJev server and its extensions remain separate.

CUA-S1 forms Optional specialist

A compact checkpoint for choosing form actions.

Hash-pinned weights run in Sys1’s TypeScript scorer when explicitly selected. This is checkpoint support, not Cua’s browser-automation stack.

llama.cpp Local GGUF runtime

Native inference for local language models, through node-llama-cpp.

Managed local loading and cancellation. Sys1 maps first-token probabilities to decision answers; setup offers compact Qwen3 models.

Cactus Needle Optional specialist

Local structured extraction through a native engine.

An explicitly selected adapter extracts answers using a bounded process. Confidence-derived probabilities are labelled as approximations.

One answer format. Different model behavior.

Schema compatibility makes integration simpler. It does not make models equally accurate or equally calibrated. Evaluate the model on your task before carrying over thresholds or changing defaults. Sys1 exposes adapter metadata so that distinction stays visible.

Before you begin.

What is a typed decision?

A small judgment returned in a predictable shape: noul is a yes/no probability, choice selects one of your named options, and score returns a numeric result over your ordered criteria. Your app decides how to use it.

Can everything stay local?

Yes, for decision requests using local models and a local-only routing policy. Initial installation and explicit model setup download packages and weights. Hosted Jev is disabled by default. The optional Needle specialist also has a documented temporary-file and process-argument boundary; review it for sensitive inputs.

Can I replace my existing Jev client?

Use an explicit adapter and test your request sizes, question limits, cancellation, and fallback behavior. Choose auto or omit the model to allow local selection; a hosted model pin stays a pin. Keep application permissions and quality thresholds in your project. Read the adoption guide.

Does Sys1 pick the most accurate model?

Sys1 selects eligible backends using your policy, availability, configured capabilities, model size, and cost rank. It does not run a quality benchmark per request. Pin a model when you need a specific backend, and evaluate its answers on your own tasks.

What does it cost?

Sys1 is free, open-source software under the MIT license. Local inference uses your hardware. Hosted providers may charge separately under their own plans.
