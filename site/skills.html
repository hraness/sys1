System

Keep noisy test logs out of your agent’s context.

system-one-verify is a skill for Devin, Claude Code, and Codex. It runs a test or build once, saves the full log on disk, and replaces long output with the exit status and a short excerpt. In a replay of 563 real validation outputs from one developer’s Codex and Devin sessions, the skill cut the text the agent would see by 35.20%. That figure counts text, not billed tokens, and the skill has not been shown to make tasks faster.

It is the only shipped skill. Ten more ideas are research candidates that still need evidence. If your test runner has a quiet mode that keeps what you need, use that first.

When to use system-one-verify

system-one-verify ships in version 0.4.1. Use it when a check is already known to produce at least 8 KiB of output and you need its pass/fail result. It makes no model calls and needs no API key.

Before
The agent receives a long result full of passing-test lines or repeated build output.
With the skill
The same command runs once. The agent gets the exit status, a short excerpt, the number of bytes left out, and the saved log path.
When detail matters
Read the relevant lines from the private local log. Follow-up reads cost tokens and can erase the initial saving.

Use it for a status decision.

A known noisy test or build has finished; the agent needs to know whether the required check passed and keep the evidence available.

Use native tools for diagnosis.

Prefer a useful quiet reporter for routine checks, and focused log reads when investigating failures, warnings, or coverage. Do not run a check twice just to choose.

What we test: the command runs once, keeps its exit status and complete log, passes short output through unchanged, and reports a timeout or capture failure as a failure. The v0.4.1 runtime suite has 43 tests. They do not show better diagnoses or faster tasks. Runtime tests.

Limits: in one real failed check, replayed through the v0.4.0 reducer, the short result kept all seven failing test names and their shared error message but only one of the seven test call sites. The full log had all of them. Only aggregate counts and a digest of the replayed sessions are public. Failed-check replay.

None of the ten has a measured result. Fetch and research share one set of 95 web calls, so do not add their numbers together. The full scorecard has the provider splits, native controls, missing-output accounting, and the rules a candidate must meet.

Try native quiet output first. A useful quiet reporter can beat an extra wrapper. The skill helps only with known noisy checks, where the short result and the saved log are worth the local overhead.

Historical exploratory figures: 82% and 3.94%

Earlier development work reported an 82.48% smaller initial result across three successful historical Devin logs, including counted skill overhead. A separate completed Codex diagnosis pair recorded 3.94% fewer input-plus-output tokens but took 9.3 seconds longer. These are historical exploratory figures with narrower denominators; they do not change the current scorecard and do not establish billed-token savings.

The 82% calculation was (9,731 − 931 − 774) / 9,731 and only three of 24 development replays met the 8 KiB selection rule. The Codex pair had uncontrolled order and cache effects, and follow-up reads can erase an initial saving. Historical results notes.

Where the wrapper adds cost

Short output passes through unchanged. Always-visible discovery and follow-up reads can add context use when the skill is never invoked or when diagnosis needs the full log. Across the measured synthetic wrapper pairs, local processing added overhead; that is not a speedup.

Research candidates

Ten more skill ideas are research candidates. None is installed or available as a command, and none has a measured result. Each would have to beat a native tool, such as focused rg searches or gh run watch, on a correct, completed task.

The skill catalog lists each candidate’s proposed payoff, the native tool it has to beat, and the evidence it still needs.

Next experiments: a compact failure summary that keeps every reported failure location with a line index into the full log, and focused search that returns the source lines a task needs. To ship, a candidate needs a defined task, an independent correctness check, a strong native baseline, every overhead and follow-up cost counted, and measured completion time. The benchmark harness that compares candidates with native workflows has no results yet. Trial protocol · Benchmark protocol.

What the file-read screen found

A retrospective screen of 1,200 file reads found 74 reads repeating the exact query and output within the same session. Those repeats contained 12,485 of 1,143,648 observed read-output text tokens: just 1.09% before any reuse overhead or freshness checks. This is an optimistic deletion ceiling, not measured savings. Necessary rereads cannot be assumed redundant, and no read-cache skill ships. Screen methods and limits.

Install system-one-verify for Devin, Claude Code, or Codex.

Version 0.4.1 installs only system-one-verify. It needs Node.js 20 or later on macOS or Linux.

Install System One Skills
npm install --global https://github.com/hraness/system-one-skills/releases/download/v0.4.1/system-one-skills-0.4.1.tgz
system-one-skills install-skills --target .agents/skills

Use .claude/skills or .devin/skills for those agents. Keep your repository’s scheduler and required checks.

Run a check already known to be noisy
system-one-skills check --timeout-ms 900000 -- bun test
