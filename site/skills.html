Give your agent shorter check results.

System One Skills runs your noisy tests and builds once, returns a short result, and saves the full log. Install the system-one-verify skill for Codex, Claude Code, or Devin.

Free and open source · Node.js 20+ · macOS and Linux
No model, API key, or Sys1 installation required.

Install in your project.

Run these commands from your project’s root directory. The package provides the command; the project skill tells your agent when to use it.

Install the package and Codex skill
npm install --global https://github.com/hraness/system-one-skills/releases/download/v0.4.1/system-one-skills-0.4.1.tgz
system-one-skills --version
system-one-skills install-skills --target .agents/skills

Claude Code
system-one-skills install-skills --target .claude/skills
Devin
system-one-skills install-skills --target .devin/skills

The installer preserves customized skill files. Keep your repository’s scheduler and required checks. Version 0.4.1 and checksums.

Run your first check

Choose a test or build you already expect to produce at least 8 KiB of output. Replace bun test with that command; the timeout below is 15 minutes.

Run from the project root
system-one-skills check --timeout-ms 900000 -- bun test

The result keeps the command’s exit status. For large output it includes a short excerpt, the number of omitted bytes, and a log="…/check.log" path. Open that file for detailed diagnosis; it lives in a private temporary directory, so copy it elsewhere if you need to keep it.

Short output
Passes through unchanged. The wrapper only compacts when it can remove at least 4 KiB and return no more than half the original output.
Failed check
The command’s failure status is preserved. Read the full log when the excerpt is not enough to understand the failure.
Everyday use
Ask your agent to use system-one-verify for a known noisy check. Prefer the command’s native quiet reporter when it already gives you a useful result.

Add a second pass on code changes.

The optional sys1-review skill checks a batch of Git changes against repository rules. It uses the separate Sys1 CLI and a configured model.

Install Sys1, then run these commands in your Git repository. The preview makes no model calls. Replace src test with the paths you changed.

Install instructions, then preview a review
sys1 review setup codex
sys1 review checkpoint --worktree --model typesafe/jev-1.13.0 \
  --max-requests 10 --dry-run --json -- src test

Use setup claude-code or setup devin for those agents. Setup adds project instructions, with no automatic hooks. The bundled rules cover empty catch blocks and removed test assertions in JavaScript and TypeScript; add rules for your repository’s other conventions.

The example selects Jev, TypeSafe’s hosted decision model. Configure Jev, inspect the files and requests in the preview, then remove --dry-run to send the selected source and diff context to it. You can also choose an experimental local model or compatible server.

Review is experimental and advisory. Investigate findings before editing code and keep your tests and ordinary review. Model scores rank candidates; they are not calibrated defect probabilities.

Review guide and repository rules

Check a completion message.

The optional sys1-verify skill compares a proposed “done” message with Git state, linked pull requests, and live pages. It marks missing evidence as unverifiable.

After installing Sys1, save the message outside your worktree, then confirm the input type and model route:

Install instructions, then preview a message check
sys1 verify setup codex
sys1 verify --message /tmp/final-message.txt \
  --model typesafe/jev-1.13.0 --dry-run --json

Use setup claude-code or setup devin for those agents. The preview reports the input type and model route without model calls or page fetches. Read the message file and inspect its links, configure Jev, then remove --dry-run to evaluate. A plain message contains no test-command transcript, so claims about passing checks may remain unverifiable.

Completion checks are experimental and advisory. A contradiction exits with status 7; a result without contradictions does not prove the task is complete. The sys1-verify skill checks claims using a model; system-one-verify above shortens command output.

Evidence sources, privacy, and exit codes

What has been measured.

A September 20, 2026 replay of 563 validation outputs returned 35.20% less text: 1,163,594 bytes became 754,006 bytes.

The replay used one developer’s Codex and Devin sessions and counted UTF-8 text bytes. It measured the first tool result, excluding skill discovery and later log reads. It does not establish billed-token, cost, or whole-task time savings. Read the scorecard and method.

Later task trials did not demonstrate whole-task token savings. A separate 60-run completion study stayed below its registered threshold for trying an automatic hook, so no hook trial followed. Those results support deliberate use on a task you understand. Read the completion study.
