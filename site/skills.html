Skills for reviewing agent work.

Give an agent reusable instructions for reviewing Git changes, checking its completion claims, or keeping noisy test output short. These workflows fit different repositories: you choose the files, rules, model, and check command.

Sys1 ships sys1-review for code-review candidates and sys1-verify for completion claims. Install either project skill for Codex, Claude Code, or Devin. The separate system-one-verify skill only captures and shortens test or build output; it needs no Sys1 backend or API key.

Review a batch of changes

sys1-review tells your agent when to preview a checkpoint, investigate findings in the code, and record feedback. Install the same workflow for Codex, Claude Code, or Devin, then choose the changes and rules for your repository.

The bundled rules check newly empty catch blocks and removed test assertions in JavaScript and TypeScript. Add and evaluate repository rules for other conventions or languages.

Run inside your Git repository after installing Sys1
sys1 review setup codex --dry-run --json
sys1 review setup codex
sys1 review checkpoint --staged --model typesafe/jev-1.13.0 \
  --max-requests 10 --dry-run --json -- src test

Use setup claude-code or setup devin for those agents. Setup writes project instructions and installs no automatic hooks. The CLI is also available to other agents.

The example selects Jev, TypeSafe’s hosted decision model. Enable it and provide your own environment credential before evaluating. The preview lists the selected source, rules, skips, and request count; repeat without --dry-run when the selected source is ready to send. You can also select an experimental local model or a compatible server.

Review is experimental and advisory. Its scores rank candidates, not calibrated defect probabilities. Keep your tests and ordinary review, investigate candidates before changing code, and record whether they were useful, incorrect, or unverifiable.

Check the completion message

The sys1-verify project skill runs sys1 verify to compare an agent’s claims with reachable evidence from Git, linked pull requests, and fetched pages. Use it to investigate claims that work was committed, merged, or made live.

Install the skill, then preview a saved message
sys1 verify setup codex --dry-run --json
sys1 verify setup codex
sys1 verify --message /tmp/final-message.txt \
  --model typesafe/jev-1.13.0 --dry-run --json

Use setup claude-code or setup devin for those agents. The skill can be installed independently of sys1-review. Save the message outside the Git worktree (/tmp/final-message.txt here; choose an equivalent path on Windows). Run inside the task repository, inspect the preview, and repeat without --dry-run to send the message and any fetched page text to the selected backend. Devin can supply the message and recent check-command results from a local session; other agents pass a file or stdin.

This command is experimental and advisory. Contradictions exit 7; missing evidence is reported as unverifiable. A result without contradictions does not prove that the work is finished. Evidence sources and limits.

Try decision workflows from source

Use experimental profiles to explore decisions during an agent's work. Each profile fixes the questions and model route while accepting new input. These experiments require a Sys1 source checkout, Bun, and the project dependencies; they are separate from the installed review and verification skills.

Failure triage
Suggest a read-only investigation from a failed command's diagnostics, such as checking an assertion, dependency, or access requirement.
Excerpt relevance
Rate how directly an excerpt addresses a task, from unrelated text to a direct answer.
Claim support
Compare a claim with a supplied excerpt and identify support, contradiction, or insufficient evidence. The result does not verify the excerpt's accuracy.

The profile evaluator checks labeled examples offline before you opt into model calls. Its reports retain errors and skipped examples alongside per-question results. The included synthetic examples are small screening sets; evaluate a profile on your own tasks before relying on it.

Keep noisy check output short

The separate System One Skills package ships system-one-verify in version 0.4.1. Use it when a check is already known to produce at least 8 KiB of output and you need its pass/fail result. It makes no model calls and needs no API key.

Before
The agent receives a long result full of passing-test lines or repeated build output.
With the skill
The same command runs once. The agent gets the exit status, a short excerpt, the number of bytes left out, and the saved log path.
When detail matters
Read the relevant lines from the private local log. Follow-up reads cost tokens and can erase the initial saving.

Use it for a status decision.

A known noisy test or build has finished; the agent needs to know whether the required check passed and keep the evidence available.

Use native tools for diagnosis.

Prefer a useful quiet reporter for routine checks, and focused log reads when investigating failures, warnings, or coverage. Do not run a check twice just to choose.

Runtime checks: the command runs once, keeps its exit status and complete log, passes short output through unchanged, and reports a timeout or capture failure as a failure. The v0.4.1 runtime suite has 43 tests. They do not show better diagnoses or faster tasks. Runtime tests.

Limits: in one real failed check, replayed through the v0.4.0 reducer, the short result kept all seven failing test names and their shared error message but only one of the seven test call sites. The full log had all of them. Only aggregate counts and a digest of the replayed sessions are public. Failed-check replay.

Try native quiet output first. A useful quiet reporter can beat an extra wrapper. The skill helps only with known noisy checks, where the short result and the saved log are worth the local overhead.

Historical exploratory figures: 82% and 3.94%

Earlier development work reported an 82.48% smaller initial result across three successful historical Devin logs, including counted skill overhead. A separate completed Codex diagnosis pair recorded 3.94% fewer input-plus-output tokens but took 9.3 seconds longer. These are historical exploratory figures with narrower denominators; they do not change the current scorecard and do not establish billed-token savings.

The 82% calculation was (9,731 − 931 − 774) / 9,731 and only three of 24 development replays met the 8 KiB selection rule. The Codex pair had uncontrolled order and cache effects, and follow-up reads can erase an initial saving. Historical results notes.

Where the wrapper adds cost

Short output passes through unchanged. Always-visible discovery and follow-up reads can add context use when the skill is never invoked or when diagnosis needs the full log. Across the measured synthetic wrapper pairs, local processing added overhead; that is not a speedup.

Further compact-output research

The System One Skills v0.4.1 catalog records ten more ideas. That release installs none of them. Each proposed skill would need evidence that it improves a completed task over native tools, such as focused rg searches or gh run watch.

The skill catalog lists each candidate’s proposed payoff, the native tool it has to beat, and the evidence it still needs.

Proposed next experiments at that revision: a compact failure summary that keeps every reported failure location with a line index into the full log, and focused search that returns the source lines a task needs. To ship, a candidate needs a defined task, an independent correctness check, a strong native baseline, every overhead and follow-up cost counted, and measured completion time. The benchmark harness that compares candidates with native workflows has no results yet. Trial protocol · Benchmark protocol.

What the file-read screen found

A retrospective screen of 1,200 file reads found 74 reads repeating the exact query and output within the same session. Those repeats contained 12,485 of 1,143,648 observed read-output text tokens: just 1.09% before any reuse overhead or freshness checks. This is an optimistic deletion ceiling, not measured savings. Necessary rereads cannot be assumed redundant, and no read-cache skill ships. Screen methods and limits.

Install system-one-verify for Devin, Claude Code, or Codex.

Version 0.4.1 installs only system-one-verify. It needs Node.js 20 or later on macOS or Linux.

Install System One Skills
npm install --global https://github.com/hraness/system-one-skills/releases/download/v0.4.1/system-one-skills-0.4.1.tgz
system-one-skills install-skills --target .agents/skills

Use .claude/skills or .devin/skills for those agents. Keep your repository’s scheduler and required checks.

Run a check already known to be noisy
system-one-skills check --timeout-ms 900000 -- bun test
