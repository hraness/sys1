One focused skill.
The full check still runs.

system-one-verify is for pass/fail checks that earlier runs have shown to emit at least 8 KiB. Use your native tools for short output or detailed log analysis.

Run once

The command runs with its original arguments and working directory. Its exit status reaches your agent.

Read the useful evidence

Short output passes through. Long output is reduced only when the result is at least 50% and 4 KiB smaller. Omissions are explicit.

Keep the full log

The private local log remains available at the printed path. Read it for warnings, coverage, or diagnosis; an excerpt cannot answer every question.

Choose this from known output size. Do not run a check twice just to decide whether to use the skill. Preserve your repository’s scheduler and required gates.

Add it to your agent.

Install the versioned runtime, then copy the skill into your agent’s skill directory. The release includes a SHA-256 checksum.

Install System One Skills
npm install --global https://github.com/0thernet/system-one-skills/releases/download/v0.4.0/system-one-skills-0.4.0.tgz
system-one-skills install-skills --target .agents/skills

Use your agent’s registry, such as .claude/skills or .devin/skills, when appropriate. Existing modified skill files are never silently overwritten.

Arguments after -- go directly to the command. Use an explicit shell for pipes or chained commands, and keep any required host scheduler outside system-one-skills.

Where SYS1 fits.

Two tools for the small operations inside an agent loop.

SYS1

A decision interface for your application: typed yes/no answers, choices, and scores across local models, hosted Jev, and compatible servers. Use its Node/Bun client, embedded Bun router, or local HTTP daemon.

System One Skills

A deterministic validation workflow. It runs commands and reduces noisy logs without a model, API key, or SYS1 installation. Installing either project does not configure the other.

What the evidence shows.

The shipped skill has a measured use for noisy logs. Better whole-task reliability, billed savings, and faster completion remain unproven.

Tokens

Of 24 real Devin validation excerpts, three met the 8 KiB rule. They fell from 9,731 to 931 output tokens. After 774 tokens of counted skill, discovery, and invocation overhead, that leaves 8,026 net text tokens saved under o200k_base.

All three were successful checks used during development. The 21 short cases would add 258 first-use tokens each if invoked unnecessarily. Calibration results and limits.

Reliability

All 24 archived-text replays passed ten scoped preservation checks. A separate runtime suite passed 25 tests covering capture, exits, fault handling, and installation.

These support specific contracts, including retained logs and explicit omissions. They do not establish better diagnosis or agent-task success. Reading the full log may still cost tokens and time. Correctness coverage.

Performance

Across 140 synthetic native/wrapper pairs, the wrapper added 41.82 ms median and 48.37 ms p95 wall time on a shared macOS arm64 host with Node 24.20.0.

These are paired overhead measurements, not a task speedup or performance guarantee. Four short failure fixtures were negative controls. Benchmark setup and results.

What the next studies found

A previously unused historical cohort yielded 14 selected validation replays: two Claude and twelve Devin. All were below 8 KiB, so none qualified under the fixed routing rule. Invoking it on every case would add an estimated 3,612 first-use text tokens. This adds no noisy-log savings, and always-visible discovery overhead on unused tasks remains unmeasured. Unused-cohort results.

The CI pilot found 128 Devin status calls and resolved 32 to run/context identities. Only two groups repeated; their queries differed, and neither established avoidable model polling. system-one-ci remains a research candidate. CI pilot results.

What earns a place in the pack

Compare every candidate with the best practical native tool on unseen complete tasks. Check correctness independently; count loading, discovery, model calls, retries, log reads, and repairs. Include unused tasks. The trial protocol requires at least 30 independently audited task/session clusters per declared scope. Correctness failures or material latency regressions block adoption; token savings cannot offset them.
